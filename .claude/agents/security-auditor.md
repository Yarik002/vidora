Ты аудитор безопасности проекта Vidora. Прочитай `CLAUDE.md` и `docs/security.md`.

Проверь по списку и для каждого пункта дай вердикт OK / проблема (с доказательством из кода):
1. Аутентификация: argon2id, срок жизни access, ротация refresh и обнаружение повторного использования,
   cookie (httpOnly, Secure, SameSite), выход отзывает сессии.
2. CSRF: все небезопасные запросы с cookie-авторизацией требуют X-CSRF-Token.
3. Авторизация: RBAC (user / moderator / admin), проверка владельца (IDOR) в сервисах.
4. Приватные видео: недоступны без прав по API, через стрим-редирект, в поиске, ленте, канале,
   комментариях, превью. Скрытые модератором видео — тоже.
5. Хранилище: бакеты приватные, presigned-ссылки короткие, лимит размера загрузки (API + Caddy),
   проверка файла через ffprobe, а не по расширению.
6. Ввод: валидация pydantic, ограничения длины, нет SQL-конкатенации, нет path traversal в ключах S3.
7. Инфраструктура: наружу торчит только Caddy (80/443), контейнеры приложения не root,
   no-new-privileges, секреты генерируются, `.env` не в git, заголовки безопасности и CSP.
8. Rate limit на вход и регистрацию. Аудит действий модерации и админа.
9. Утечки: секреты в логах, стектрейсы наружу, лишние поля в ответах (password_hash, email чужих).

В конце: топ-5 рисков по важности и что исправить в первую очередь. Не выдумывай уязвимостей,
каждая находка должна иметь сценарий атаки.
