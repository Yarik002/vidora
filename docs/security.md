# Безопасность

## Модель угроз

**Что защищаем:** приватные и скрытые видео (файлы и метаданные), аккаунты и сессии,
права модераторов и админов, целостность счётчиков и журналов, доступность сервиса,
секреты инфраструктуры (БД, Redis, ключи S3, ключ подписи JWT).

**От кого:**
1. Аноним из интернета: перебор паролей, перечисление объектов, доступ к чужим файлам по прямой ссылке.
2. Обычный зарегистрированный пользователь: IDOR (чужие видео, комментарии, плейлисты), повышение
   прав, спам, загрузка вредоносных файлов, исчерпание ресурсов.
3. Чужой сайт в браузере жертвы: CSRF, кликджекинг, XSS через пользовательский контент.
4. Злоумышленник, получивший выполнение кода в одном контейнере (например, через уязвимость
   в ffmpeg): чем меньше у контейнера прав и секретов, тем меньше ущерб.

**Границы доверия:** интернет → Caddy (единственный открытый сервис) → API / MinIO-шлюз →
внутренняя сеть (Postgres, Redis, MinIO, воркер). Файлы пользователей — недоверенный ввод
для ffmpeg.

## Меры

### Аутентификация и сессии
| Мера | Где |
|---|---|
| Пароли: argon2id (RFC 9106, m=64 МБ, t=3, p=4), перехеширование при смене параметров | `core/security.py` |
| Одинаковое время ответа для существующих и несуществующих логинов (фиктивная проверка хеша), одинаковый текст ошибки | `core/security.py`, `services/auth_service.py` |
| Политика пароля: ≥ 8 символов, не только буквы и не только цифры | `schemas/auth.py` |
| Access JWT HS256 на 15 минут, привязан к сессии (`sid`): при каждом запросе проверяется, что сессия не отозвана и пользователь активен. Выход и блокировка действуют сразу, а не через 15 минут | `api/deps.py`, `repositories/users.py` |
| Refresh-токен: случайные 32 байта, в БД только SHA-256. Ротация при каждом обновлении, «семья» токенов: повторное использование старого токена (кража) отзывает всю семью и пишется в аудит. Окно 15 с на гонку двух вкладок | `services/auth_service.py` |
| Cookie: `__Host-vid_at` (httpOnly, Secure, SameSite=Lax, Path=/), `vid_rt` (httpOnly, Secure, SameSite=Strict, Path=/api/v1/auth: refresh не уходит на остальной API) | `api/v1/auth.py` |
| Ключ JWT ≥ 32 символов, иначе приложение не стартует | `main.py` |
| Swagger/API-клиенты: OAuth2 password flow, Bearer-токен, без cookie | `api/v1/auth.py` |

### CSRF, XSS, кликджекинг
- Double-submit cookie: `vid_csrf` (читаемая JS) должна совпасть с заголовком `X-CSRF-Token` для
  всех небезопасных запросов к `/api`, плюс проверка `Origin`. Пропуск только для `Bearer`
  (там cookie не используются вообще) и для `/auth/token` (не ставит cookie). `core/csrf.py`.
- CORS не включён: чужой сайт не может отправить кастомный заголовок без preflight.
- CSP для приложения: `default-src 'self'; script-src 'self'; style-src 'self'; object-src 'none';
  frame-ancestors 'none'`, без `unsafe-inline` для скриптов. React экранирует пользовательский
  текст. Ответы хранилища: `CSP: default-src 'none'; sandbox`.
- `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy`,
  `Permissions-Policy`, `Cross-Origin-Opener-Policy`, HSTS при реальном домене. `deploy/caddy/Caddyfile`.
- Редирект после входа принимает только относительные пути (`/x`, не `//evil`): `pages/Auth.tsx`.

### Авторизация
- RBAC: `require_moderator`, `require_admin` (`api/deps.py`). Модератор: жалобы, скрытие и
  восстановление видео, удаление комментариев. Админ: ещё роли и блокировки. Админ не может
  понизить или заблокировать сам себя.
- IDOR: изменение и удаление видео только владельцем или админом (`_get_own_or_admin`),
  плейлистов только владельцем, комментариев автором, владельцем видео или модератором.
  Чужим объектам отвечаем **404, а не 403**, чтобы не раскрывать их существование.
- **Одна функция доступа к видео** `services/access.py`: используется в карточке видео, стриме,
  комментариях, ответах, реакциях, связанных видео, плейлистах, жалобах. Ленты, поиск и канал
  фильтруются одним SQL-условием `listed_condition()`. Приватное видео видят владелец, staff и те,
  кому выдан доступ. Скрытое модератором видео видят только владелец и staff.

### Хранилище и раздача
- Бакеты приватные, анонимный доступ выключен. Приложение работает под отдельным пользователем
  MinIO с политикой только на свои два бакета. Root-ключи есть только у одноразового `minio-init`.
- Загрузка: presigned URL на каждую часть (1 час), ключи объектов только из UUID.
  Размер проверяется трижды: при создании (≤ 1 ГБ), Caddy режет каждый запрос части до 16 МБ,
  после сборки реальный размер должен совпасть с заявленным.
- Файл проверяется **по содержимому** (ffprobe): должен быть видеопоток, длительность от 0,5 с
  до 3 ч, разумное разрешение, контейнер не картинка и не плейлист.
- ffmpeg получает `-protocol_whitelist file` и белый список демультиплексоров: файл не может
  заставить ffmpeg открыть URL во внутренней сети или локальный файл (SSRF через HLS/concat).
- Раздача: API проверяет права и отвечает 302 на ссылку, подписанную на 15 минут
  (`Cache-Control: no-store` у редиректа). Перемотку (Range) обслуживает MinIO.
  После отзыва доступа уже выданная ссылка живёт не дольше 15 минут.
- Шлюз `/storage` в Caddy пропускает только `PUT` частей в `vidora-raw/uploads/*` и
  `GET/HEAD` в `vidora-media/videos/*`. Admin API MinIO, листинг бакетов и всё прочее: 404.

### Ограничение злоупотреблений
| Что | Лимит |
|---|---|
| Вход (по IP) / регистрация (по IP) | 10 / 5 в минуту |
| Неудачные входы в один аккаунт (с любых IP) | 10 за 15 минут, затем 429 |
| Создание загрузок / активные загрузки | 30 в час / 5 одновременно на пользователя |
| Комментарии / жалобы | 20 в минуту / 20 в час на пользователя |
| Одна открытая жалоба от человека на видео или комментарий | частичный UNIQUE-индекс |
| Новые имена для on-demand TLS | не больше 20 |
| Размер тела запроса к API | 2 МБ (Caddy) |

Счётчики в Redis (фиксированное окно, `SET NX EX` + `INCR` в одной транзакции).

### Инфраструктура
- Наружу публикуется только Caddy (80/443). Postgres, Redis, MinIO, API и воркер в сети
  `internal: true`: без опубликованных портов и без выхода в интернет. CI проверяет это
  после деплоя.
- Контейнеры приложения и Caddy работают не от root (uid 10001), `read_only` корневая ФС,
  `cap_drop: ALL`, `no-new-privileges`. MinIO (Bitnami) тоже не root, Postgres и Redis
  сбрасывают права в своём entrypoint.
- **Секреты по сервисам:** api и воркер получают только нужное (ключи S3 приложения,
  пароль Redis, ключ JWT, роль БД приложения). Root-ключи MinIO есть только у `minio-init`,
  пароль владельца БД только у `migrate`, пароли админа и демо только у разовых
  `create_admin`/`seed`.
- **БД с минимальными правами:** api и воркер подключаются ролью `vidora_app` (только
  SELECT/INSERT/UPDATE/DELETE, без DDL, без доступа к `alembic_version`). Миграции идут под владельцем.
- Секреты генерирует `scripts/gen_env.sh` (`/dev/urandom`), файл `.env` с правами 600, в git не
  попадает. Ротация: `scripts/rotate_secret.sh KEY` (значения не печатаются).
- Внутренний CA Caddy, сертификат выпускается по требованию для IP, по которому открыли сервер.
  Разрешение на выпуск даёт API, снаружи эта ручка закрыта. С доменом используется Let's Encrypt и HSTS.

### Аудит
`audit_log` (входы, неудачные входы, регистрация, загрузки, удаление видео, выдача доступа,
обнаружение кражи refresh, все действия модерации) и `moderation_actions` (кто, что, по какой
жалобе, причина). Записываются в той же транзакции, что и само действие.

## Как проверяется
Автотесты (`backend/tests`) на критичное: приватные видео недоступны ни по API, ни по стриму, ни
в ленте и поиске; роли; модерация скрывает видео везде; IDOR; CSRF и чужой Origin; ротация и
кража refresh; отзыв сессии при выходе и бане; rate limit; файл-не-видео отклоняется по
содержимому; несовпадение размера; неподписанный доступ к хранилищу. E2E-скрипт проверяет то же
через Caddy. Аудит кода проводил агент `security-auditor` (`.claude/agents/`), его находки и
что с ними сделано: `docs/ai-workflow.md`.

## Принятые риски и что улучшить
- **Swagger на `/docs`** обязателен по заданию. Он грузит JS с jsdelivr без SRI. Если CDN
  скомпрометирован, скрипт выполнится на нашем домене. Смягчение: отдельная CSP для `/docs`.
  Для прода лучше раздавать swagger-ui со своего сервера или закрыть `/docs`.
- **`deploy.sh` печатает тестовые пароли** в конце: этого требует сценарий проверки. В CI
  вывод скрыт (`VIDORA_HIDE_SECRETS=1`).
- **Блокировка аккаунта после 10 неудачных входов** может быть использована, чтобы на 15 минут
  не пустить конкретного пользователя. Это осознанный компромисс против перебора.
- **Образ MinIO** заморожен (Bitnami legacy): обновлений безопасности не будет. Хранилище
  заменяется на любой S3 (SeaweedFS, Garage, AWS) через `S3_ENDPOINT` и ключи.
- **Нет антивируса и проверки контента**: видео перекодируется, исходник хранится в приватном
  бакете и пользователям не отдаётся.
- **Бэкапы:** в проекте их нет. Для прода: `pg_dump` по расписанию плюс репликация бакета
  (`mc mirror`) на другой S3. Тома Docker нужно бэкапить целиком.
- **Ротация инфраструктурных секретов** (пароль владельца БД, Redis, MinIO) требует ручных шагов:
  сервисы хранят старое значение у себя. `JWT_SECRET`, `ADMIN_PASSWORD`, `DEMO_PASSWORD`,
  `APP_DB_PASSWORD` ротируются скриптом и переразвёртыванием.
