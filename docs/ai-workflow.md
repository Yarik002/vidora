# Как проект делался с ИИ

Весь код написан Claude Code (модель Claude Opus) в одной сессии с субагентами. Человек
выступал постановщиком задач и ревьюером: формулировал требования, утверждал решения, смотрел
отчёты по этапам. Исходные диалоги (`*.jsonl` из `~/.claude/projects/<проект>/`) лежат в архиве
сдачи без правок: по ним видно каждый промпт, каждую команду и каждую ошибку.

## Обвязка (что лежит в репозитории)

| Файл | Зачем | Как реально использовался |
|---|---|---|
| `CLAUDE.md` | архитектура, правила слоёв, правила безопасности (секреты, 404 вместо 403), git-правила, **чек-лист «как проверять перед словом готово»** | агент сверялся с ним; ревьюер и аудитор проверяли код против него |
| `.claude/agents/code-reviewer.md` | ревьюер: слои, транзакции, счётчики, N+1, IDOR, тесты | запущен на этапе 4, 14 находок, исправлено 13 |
| `.claude/agents/security-auditor.md` | аудитор по модели угроз | запущен на этапе 4, 12 находок, исправлено 10, 2 приняты как риск |
| `.claude/commands/precommit.md` | `/precommit`: что уходит в коммит, поиск секретов в diff, линтер, тесты, сборка фронта | порядок проверки перед каждым коммитом |
| `.claude/commands/e2e.md` | `/e2e`: поднять стек и прогнать сквозной сценарий | после каждого этапа |
| `.claude/settings.json` | только **запреты**: чтение `.env`, force push, `reset --hard`, rebase | сработал не раз, см. ниже |

`.mcp.json` в проекте нет: проектных MCP-серверов не подключали. Для проверки интерфейса
использовался встроенный браузер Claude Code Desktop (его MCP-инструменты идут с самим
приложением, а не из конфигурации проекта): скриншоты страниц, чтение DOM, сетевые запросы,
состояние `<video>`.

## Процесс

1. **Постановка.** Человек дал развёрнутую постановку: ТЗ, критерии оценки, свои предложения
   по архитектуре, ограничения окружения, правила честности («работает» только после
   реального запуска) и требования к безопасности диалога. Первым шагом ИИ прочитал `TZ.docx`,
   сверил его с постановкой, проверил окружение (только чтение) и предложил план с 7 ключевыми
   решениями. Человек утвердил всё одним сообщением.
2. **Декомпозиция по этапам**, каждый в своей ветке, merge `--no-ff` и тег:
   - `v0.1-skeleton`: репозиторий, обвязка, compose со всеми сервисами, `deploy.sh` с первого дня;
   - `v0.2-core`: сквозной сценарий проверки (регистрация, загрузка, обработка, просмотр,
     лайк, комментарий) и тесты на него;
   - `v0.3-screens`: каналы, подписки, плейлисты, поиск, модерация, студия, демо-данные;
   - `v0.4-hardening`: ревью и аудит агентами, исправления, CI, документация;
   - `v1.0`: полировка, установка из чистого клона.
   Приоритет «сначала целиком, потом вширь»: к концу этапа 2 продукт уже проходил главный
   сценарий через настоящий Caddy, MinIO и воркер.
3. **Внутри этапа:** модели и миграция, потом сервисы, потом роутеры, потом тесты, потом UI.
   Каждый кусок проверялся сразу: ruff → pytest на реальных сервисах → e2e через Caddy →
   просмотр в браузере.
4. **Независимая проверка субагентами.** Ревьюер и аудитор работали параллельно, только на чтение
   и без доступа к `.env`, пока основной агент делал CI. Их отчёты сверялись с кодом, каждая
   находка либо исправлялась с регресс-тестом, либо явно принималась как риск в `docs/security.md`.

## Как проверялся результат ИИ

- **Тесты на настоящих сервисах**, а не на моках: Postgres, Redis, MinIO и ffmpeg из того же
  compose, отдельная БД `vidora_test`, миграции Alembic как в проде. 53 теста: приватность,
  роли, модерация, IDOR, CSRF, ротация и кража refresh, rate limit, проверка файла по содержимому,
  параллельные лайки, поиск с опечатками.
- **E2E-скрипт** `scripts/e2e.py` (только стандартная библиотека) проходит сценарий через Caddy по
  HTTPS, как браузер: multipart в S3, ожидание обработки, 302 и Range 206, лайк, комментарий,
  приватность.
- **Браузер:** каждый экран открывался и проверялся глазами. Состояние плеера проверялось через
  DOM (`readyState`, `currentTime`), потому что скриншот не захватывает аппаратно декодируемое видео.
- **Миграции:** `upgrade → downgrade → upgrade` и `alembic check` (модели совпадают со схемой).
- **Деплой:** `deploy.sh` в чистом privileged-контейнере `ubuntu:24.04` (Docker-in-Docker, без
  systemd) и в CI на свежих раннерах Ubuntu 22.04/24.04. Это не ВМ, и нигде не написано, что
  «проверено на чистой ВМ».
- **Значения из ответа API не принимались на веру:** при сомнении считали прямо в PostgreSQL
  (`word_similarity` для порога поиска) или смотрели реальные заголовки (curl).

## Что пришлось исправлять за ИИ (и что он поймал сам)

Подробно с причинами: `docs/NOTES.md`. Коротко:

| Что | Кто заметил |
|---|---|
| Утечка сгенерированного пароля в лог: pydantic вставил значение в текст ошибки. Пароль ротирован, генератор и обработка ошибок исправлены | сам агент, по выводу команды |
| Том `/work` с владельцем root: ffmpeg молча писал в tmpfs на 64 МБ, большие видео упали бы | сид, прогнанный через настоящий конвейер |
| Опечатки в поиске не находились (`%` вместо `word_similarity`) | тест |
| `FOR UPDATE` с eager-join | тест |
| Флаг «изменено» после лайка, счётчик плейлиста после удаления видео, вечный `upload_incomplete` при повторе, поиск из пробелов | ревьюер |
| Весь `.env` в контейнерах, SSRF через ffmpeg, открытый admin API MinIO через `/storage`, CSRF-исключение шире нужного | аудитор |
| Шаблонные мелочи в коде агента (`if True:`, заглушки `_ = X`, неиспользуемый подзапрос), которые агент убрал при самопроверке перед коммитом | сам агент |
| Тест со слабой проверкой (`== ["240p"] or ...`) ужесточён | сам агент |

## Где ограничения ИИ потребовали решений человека или среды

- **Права.** Попытка агента записать себе разрешения (`allow`) в `.claude/settings.json` была
  заблокирована классификатором Claude Code. Решение: в файле только запреты. Агент не
  расширяет свои полномочия.
- **Секреты.** Запрет на чтение `.env` действовал всю сессию: агент ни разу не видел значений
  (кроме одного инцидента выше, после которого значение сразу сменили). Ротация шла
  скриптом `scripts/rotate_secret.sh`, который ничего не печатает.
- **Публикация.** Создание репозитория на GitHub и отправку архива агент делать не может без
  явного «да» человека.

## Промпты

Все промпты в jsonl. Ключевые постановки:
1. Стартовая постановка (роль: «агент — исполнитель, человек — архитектор и ревьюер»),
   с критериями оценки, предложениями по архитектуре и правилами честности.
2. «Выполни тестовое полностью по плану и подготовь меня к сдаче.»
3. Субагентам: «Ты агент `security-auditor` / `code-reviewer`. Прочитай свою инструкцию в
   `.claude/agents/…`, только чтение, не открывай `.env`, находки с файлом, строкой,
   сценарием и исправлением, не выдумывай».
